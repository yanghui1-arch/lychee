# 实时桌面字幕

## 运行

在相邻 `lychee-server` 项目中使用其现有 Docker 配置：

```powershell
Set-Location ..\lychee-server
docker compose up -d --build
docker compose ps
curl.exe --fail http://127.0.0.1:8000/health/ready
```

服务器 `.env` 需已设置 MySQL、LLM 与 ASR 配置。新数据库按服务器 [开发文档](../../lychee-server/docs/development.md) 初始化，已有数据库按其文档迁移。客户端开发不需要修改服务器源码；本次也未修改它。

服务器必须有有效登录会话和足够积分。客户端账户 UI 尚未接入，当前由本机运行环境提供登录令牌：

```powershell
# 在本机终端安全设置；不要提交到仓库或发送到聊天记录。
$env:LYCHEE_ACCESS_TOKEN = '<有效登录会话的 access_token>'
# 可选；不设置时从 LYCHEE_TRANSLATE_URL / 打包默认地址派生。
$env:LYCHEE_SPEECH_URL = 'ws://127.0.0.1:8000/v1/translate/speech'
& .\build\bin\lychee.exe
```

也可配置系统用户环境变量后重新启动客户端，使进程继承新值。令牌不进入前端；Go 用 `Authorization: Bearer` 发送。未配置时开关会给出明确提示；无效或过期凭证、余额不足与上游错误使用服务器的错误消息展示。不会自行创建用户、增加积分、绕过鉴权或重放旧音频。

### 本机开发测试凭证

开发库尚未接入 Steam 登录时，可显式运行客户端仓库的测试启动脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-SubtitleTest.ps1
```

脚本连接相邻服务器现有的 Docker 容器，在开发数据库中创建专用账号 `local-subtitle-test`，首次分配与正式注册相同的 16,500 测试积分；已有账号不会重置或补充余额。这是可识别的开发标识，不是真实 Steam ID。脚本仅适用于本机开发 API，不应对生产数据库执行。

脚本创建 24 小时有效的随机会话，数据库只存 SHA-256 哈希，并通过 `/v1/users/me` 验证。凭证写入本机用户环境变量并由启动的 exe 继承，不输出到终端或写进仓库。后续运行会复用仍有效的测试凭证；过期时自动重新签发。它不修改服务器源码，也不改动服务器鉴权逻辑。

`-RefreshToken` 强制签发新凭证，`-Hours 2` 可设置较短有效期，`-NoLaunch` 只配置而不打开应用。例如：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-SubtitleTest.ps1 -RefreshToken -Hours 24
```

已有客户端进程不会自动继承新环境变量；先退出，再通过该脚本启动即可。测试仍会调用已配置的真实 ASR / 翻译供应商并按服务器规则扣减测试积分。

## 音频链路

1. WASAPI 监听所选应用进程树或默认输出设备，输出 16 kHz、单声道、PCM s16le。约每 200ms 复制到容量 50 块的队列，约 10 秒；超出即明确停止，避免积压导致无限延迟。
2. 本地 Silero VAD v6.2 按 512 个采样 / 32ms 推理，与采集包边界无关。连续两帧概率 ≥ 0.5 开始语音；保留最多十帧（320ms）前置音频。概率 < 0.35 连续四十帧后结束，保留全部 1.28s 自然尾部静音。
3. 检测到语音才建立 WebSocket。发送 `start`（语言、16000 Hz、`pcm_s16le`、单声道），等待 `ready` 后，以实时节拍发送二进制 PCM。前置音频也按采样时长发送，不突发上传。语音段内部不删除静音、不插入假静音；无语音的长空档不上传。
4. 每段结束发送 `finish`，等待最终结果和 `completed`。后续语音可立即开启新连接，不等待前段的翻译；最多三个正在上传或等待确认的会话。先完成的后段会暂存，按音频顺序显示。待显示事件按会话限制为 256 条，临时快照可合并，稳定结果不静默丢弃。
5. 采集端按实际 PCM RMS 记录最后有声时间，连续约 2.5 秒不高于 0.0001 时，清空当前页、阅读队列、待确认预览及短片段接续状态，取消旧处理上下文。采集和音量检测继续运行，监听开关保持开启；有声后创建全新的 VAD／语音流水线。语音段之间的 1.28 秒自然停顿不会立即触发清理；背景音乐或低音量语音也属于有声，不能用 VAD 的“无语音”判断视频退出。
6. 每轮接收携带递增 generation，字幕接收与清空在同一把锁下检查。清理后的旧连接即使迟到返回翻译、预览或中断事件，也不能填回屏幕；恢复音频后旧 generation 仍失效。旧处理先取消连接，异步收尾，避免阻塞 WASAPI 回调，退出时统一等待资源释放。手动停止、切换来源和采集结束不等待静音宽限，直接清空，不再排队读完旧视频。

这里只能根据所选音频来源的能量推断停播，无法精确获知网页／视频退出。全局监听时其他应用发声会延长活跃状态；持续无声的正常视频也会在宽限期后清理，恢复发声时自动继续。断线和静音清理都不重放旧音频；静音前已发送的请求仍可能产生服务器结算。

### ASR 修订错误与会话接续

`asr_committed_text_changed` 来自服务器的转写一致性检查：服务器已按临时识别快照中的标点把前缀送去翻译，后续 ASR 又实质修改了这个前缀（只改大小写、空格或标点可以容忍）。服务器会主动结束该会话，以避免旧译文和新原文错接。这不是登录凭证失效，也不是客户端阅读队列修改了原文。根因在上游识别和服务器提交时机；客户端未修改服务器源码或放宽其检查。

客户端仅对这个明确错误码接续：释放失败连接，保留已定稿字幕，按原会话顺序将未定稿预览标为未完成，然后从后续实时音频建立新会话。正在发送和等待 `finish` 确认的会话都适用；错误通知会说明该片段可能不完整，监听开关保持开启。旧音频不缓存重放，失败时服务器未返回的文字无法恢复，发送失败时的一小块音频也不重传。新会话不保留旧会话的服务端上下文。

30 秒内最多允许三次接续，第四次明确停止并提示识别服务反复修订，防止无限重连。鉴权、积分、断网等其他错误仍正常停止。WebSocket 读取到的具体服务器错误会保留，避免被随后发送 `finish` 的通用写入失败覆盖。

每段使用独立服务器 session，服务端 ASR 时间从零计起，跨段不保留服务端翻译上下文。短于两帧的语音可能被视为噪声；持续背景音乐也可能被 VAD 误判，阈值与尾部长度集中在 `speech_vad.go`。本地采集到首个音频块约需 200ms，另有前置音频的实时发送、网络、ASR 与翻译耗时；不能将 VAD 推理耗时当成端到端延迟。

## 字幕快照与显示

- `transcript` 按 `(session_id, sentence_id)` 缓存完整快照，允许临时修订与最终空文本撤销；定稿后忽略迟到修订。转写事件不直接触发显示，不单独渲染原文。
- `translating` 保存片段源文和 `sentence_ids`；`translation_preview` 替换该 `sequence` 的完整快照，重复或回退预览不重复追加。预览只合并缓存，收到 `translation` 确认后，完整片段才进入阅读队列；同一片段不会因多次快照而重复播放。
- 每个 `(session_id, sequence)` 对应独立的原文／译文队列项，不把整句累计快照反复入队。第一帧即同时显示可用的两种语言。优先使用该片段的 `source_text`；缺少片段源文时回退到对应句子的缓存转写，两者都没有就只渲染译文。可恢复的 ASR 修订错误将尚未确认的预览标记为未完成后保留到队列；监听结束则清空。
- 画布固定为 **1000 × 240 逻辑像素**，按 DPI 缩放；窄屏按显示器工作区约束宽度。宽高不依赖文字长度、换行、字号或有无原文。预览固定为桌面画布的 0.46 倍，原文和译文各最多两行，只有译文时居中，不为缺失原文保留空行。
- 固定画布的空白部分完全透明。每种语言的可见底色只包围实际字形，水平留白约 0.36 倍字号、垂直留白约 0.16 倍字号；描边和柔和字影也随字号及 DPI 缩放。两块底色重叠时不叠加变黑，空文本不绘制底色。设置页采用同样的字体相对留白，不再把整块固定画布涂黑。
- 阅读队列与接收队列独立。接收端保存完整文本，不截取尾部；显示端从头分页，只有当前页完整显示并停留后才推进文本游标。后来的片段不能覆盖前页，队列积压不会导致加速或跳字，也没有 10 秒过期清除未读内容的规则。
- 每页限制约 28 个阅读单位，并在原生窗口线程按实际显示器、DPI、字体和两行区域测量。默认每秒 12 个阅读单位：一个 CJK 字形约 1 单位、拉丁字母约 0.4 单位，即约中文 12 字／秒、英文 30 字母／秒。吐字速度与分页容量独立，提速不增加单页文字量。双语按同一进度呈现，完整显示后停留 0.8 秒；很短的页面至少显示 1.2 秒（至少 0.4 秒呈现加 0.8 秒停留），翻页淡入 180ms。UI 阻塞或电脑休眠不会让不可见的时间消耗未读内容。
- 短片段接续：整段能放入一页且不超过 12 个阅读单位时，先正常显示；队列暂时没有后续定稿时，完整显示及正常停留后再等最多 900ms，保留当前字幕。仅合并同一 WebSocket 会话、连续 sequence、同样原文可用状态的已定稿片段；不合并未完成预览。必须同时满足合并后最多 28 单位以及原生字体／DPI／两行区域的完整测量。合并时保持页面 key 和已显示前缀，只为新增后缀启动吐字计时；原文和译文继续同步，已有文字不清空、不重播、不重新淡入。可连续接续直到当前页容量不足，此后正常翻页。候选片段放不下、会话改变或 sequence 不连续时，按原顺序分页，不跳过内容。没有后续会在有限等待后清屏；持续静音或监听结束则直接清空，接续等待不能延迟清理。
- 分页优先选择空白和标点边界，并保留 Unicode 字素（组合重音、emoji、肤色和 ZWJ 序列不拆开）。服务端没有词级对齐信息，长句双语按剩余长度比例分页；一侧较短时保留上一页的短侧文本作上下文，不伪造词级对应。分页结果必须完整放入行区，不能再次静默裁成尾部；字体或显示区域变化时，重新排版当前未读页，不推进游标。
- 接收速度长期高于阅读速度时，阅读延迟自然累积，预览标签显示预计待阅读时间。已定稿文本缓冲超过约 4 MiB 后明确停止监听；持续播放期间不靠丢字或赶播压缩延迟。持续静音或结束监听属于播放生命周期结束，会主动丢弃旧缓冲，重新开启也不保留未读队列。缓冲仅在内存中保存。
- 预览与原生窗口消费同一显示帧；切换工作区、最小化主窗口继续监听。语言变化先完成旧会话再使用新语言建立连接；样式、位置和字号即时生效。
- 预览不是结算确认。可恢复的 ASR 错误中，未定稿部分标记为「译文未完成」；真正停止监听时清空。取消旧连接不代表已发送请求一定没有结算。不生成本地音频文件。

## 代码分工

| 文件 | 职责 |
| --- | --- |
| `audio.go`、`audio_windows.go` | 采集生命周期、音量、停止与语音流水线连接 |
| `audio_subtitles.go` | 音频静音宽限、字幕接收批次、旧处理取消与恢复 |
| `vad_windows.go`、`models/` | 嵌入模型和运行库、初始化推理、循环状态与资源释放 |
| `speech_vad.go` | 任意包重组、VAD 门控、前后缓冲 |
| `speech.go` | 有界队列、语音段生命周期、并行排空与背压 |
| `speech_protocol.go` | WebSocket 鉴权、握手、PCM 节拍、结果读取与超时 |
| `speech_order.go` | 相邻语音段异步返回时的显示排序与队列上限 |
| `speech_recovery.go` | 指定 ASR 修订错误的有限接续与可读提示 |
| `speech_captions.go` | 原文修订、译文快照合并、按服务器 sequence 配对 |
| `subtitle_playback.go` | 完整文本阅读队列、从头分页、字素级恒速呈现与停留时间 |
| `subtitle_continuation.go` | 短片段有限等待、原译接续、保留前缀和页面标识 |
| `subtitle.go`、`subtitle_*windows.go` | 显示节拍与原生窗口位图、淡入、位置和字体 |
| `frontend/src/features/subtitle/` | 设置页、实时预览、音量与错误提示 |

bun run --cwd frontend typecheck

测试覆盖真实 ONNX 模型加载和静音推理、任意大小音频包与 VAD 前后缓冲、采集停止时短尾处理、真实 WebSocket 握手和鉴权头、二进制 PCM、自然语音段 `finish` 后最终译文接收、缺失原文、重复和迟到快照、同句多片段、跨段乱序与断连。字幕测试使用可控时钟验证持续播放时连续突发结果的所有页面从头播放到尾、后文不覆盖前文、积压不加速、完整页停留、预览／最终结果去重、布局重排不消耗未读游标，以及字素和每个输入字节均不丢失。原生回归测试使用不同字号、窄屏和 DPI 验证真实分页能完整渲染在固定画布内。

会话恢复回归通过模拟 WebSocket 分别在音频发送中和 `finish` 阶段注入 `asr_committed_text_changed`，验证接续连接、字幕／未完成预览的顺序和零音频重放；同时验证恢复限频、其他错误不重试、并发上传时保留真正的服务端失败原因，以及监听不会被单个失败会话关闭。位图测试验证透明画布、实际字形底色、空文本无底色及不同字号下底色随文字变化。

短片段回归使用可控时钟验证后续稍晚到达时字幕不清空、连续多段追加时 key 保持稳定且已显示前缀从不缩短、完整原译不丢失或重复、无后续时等待有上限、结束监听跳过额外等待，以及跨会话／sequence 缺口／原文可用状态变化／未完成片段／长度或布局超限不误合并。重新排版保留合并后的完整文本，不沿用旧后缀的显示进度。

静音回归覆盖短暂停顿保留、低音量持续播放重置宽限、持续静音同时清空定稿与预览、旧连接取消、空闲期间不反复初始化、恢复后新旧结果隔离、手动停止时拒绝迟到尾部结果，以及取消与恢复交错时旧批次不能重新启用。
